# 08-邻居 192.168.236.48 的有限身份与服务识别

> 观察日期：2026-11-06。发起端：授权测试的 Win7 `192.168.236.49/24`。目标仅为已确认可达的 `192.168.236.48`。本次仅查询名称解析、NetBIOS 名称表，并对少数常见 TCP 端口做短超时连接测试；没有登录、读取共享、认证尝试或修改目标配置。

## 8.1 已知二层与 ICMP 特征

- IPv4：`192.168.236.48`
- 前轮 ARP 缓存 OUI：`44:37:E6`；完整 MAC 不公开。
- OUI 注册组织：Hon Hai Precision Ind. Co., Ltd.（鸿海精密）。OUI 不能确定设备品牌或型号。
- ICMP：前轮 2/2 回复，TTL=64，延迟约 0–1 ms。
- 当前 Win7 的本机主机名为 `a307`。

## 8.2 名称解析异常

对目标执行：

- `ping -a -n 1 -w 500 192.168.236.48`：输出名称 `a307`，即 `Pinging a307 [192.168.236.48]`。
- .NET `System.Net.Dns.GetHostEntry("192.168.236.48")`：返回 `a307`。
- `nbtstat -A 192.168.236.48`：没有取得远端 NetBIOS 名称表。
- `nslookup 192.168.236.48 114.114.114.114`：DNS 请求超时。
- Win7 WINS Primary/Secondary 均未配置；本机 DNS 缓存和 hosts/lmhosts 文件中未找到该地址或 `a307` 的显式记录。

Microsoft 文档说明，`nbtstat -A <IP>` 用于按 IPv4 地址查询远端 NetBIOS 名称表：[Microsoft Learn - nbtstat](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/nbtstat)。

**解释边界：** 名称解析 API 返回 `a307`，但目前无法确定它来自哪种名称解析路径，也无法证明目标真的与 Win7 使用相同主机名。可能涉及 LLMNR、未显示的解析缓存或其他本地名称解析机制；这些都只是待验证假设。不能将 `a307` 直接作为目标身份。

## 8.3 少量 TCP 连接测试

从 Win7 对单一目标 `192.168.236.48` 做短时 TCP 连接测试。每个端口等待约 600 ms；不发送应用层登录或认证数据。

| 端口 | 结果 | 可支持的判断 |
| --- | --- | --- |
| TCP/22 | 未建立连接 | 本次未观察到 SSH 监听 |
| TCP/80 | 未建立连接 | 本次未观察到 HTTP 监听 |
| TCP/443 | 未建立连接 | 本次未观察到 HTTPS 监听 |
| TCP/445 | **连接成功**，重复测试仍成功 | 该端口接受 TCP 连接；与 SMB Direct Hosting 常见端口一致，尚未完成 SMB 协议协商确认 |
| TCP/3389 | 未建立连接 | 本次未观察到 RDP 监听 |

“未建立连接”仅表示该次连接窗口内未成功建立 TCP；可能是端口关闭、防火墙过滤、服务临时不可用或超时。它不等于服务绝对不存在。

## 8.4 当前可得结论

1. `.48` 是同一 `192.168.236.0/24` 链路中可达的设备，且有稳定的 ICMP 响应。
2. 该地址的 ARP OUI 属于鸿海注册地址块，但不足以确定网卡型号或终端类型。
3. `TCP/445` 确实接受连接，值得将“SMB 兼容服务”列为优先验证方向。
4. 远端 NetBIOS 名称表查询没有返回记录；名称解析 API 却返回 `a307`，与 Win7 本机名相同。这一冲突尚未解决。
5. 不能据此判断目标是 Windows、Linux、NAS、打印机或其他设备。

## 8.5 后续边界

若要继续确认 TCP/445 的应用层协议或共享信息，需要目标设备所有者明确允许进一步检查。当前没有枚举共享、查询用户、尝试空会话或进行身份认证。优先做法是由设备所有者确认设备用途和主机名，再决定是否开展 SMB 协议协商或只读共享清单检查。

本次没有扩大扫描范围，也没有修改 Win7 或目标设备配置。
