# 07-Win7 同网段邻居可达性与 ARP 采样

> 观察日期：2026-11-06。测试发起端为个人 Windows 7 SP1 主机 `192.168.236.49/24`。本次仅对用户明确授权的同一 `192.168.236.0/24` 邻居地址做少量 ICMP Echo 和 ARP 缓存观察；未进行端口扫描、服务枚举、登录尝试或配置修改。邻居完整 MAC 不在公开报告中保存。

## 7.1 测试方法

- 对 `.46–.52` 每个地址发送 2 个 Echo Request，超时 500 ms。
- 对 `.40–.60` 中前一轮未覆盖的地址各发送 1 个 Echo Request，超时 300 ms。
- 对 Win7 ARP 缓存中已有的 `.10`、`.12`、`.20`、`.25`、`.28`、`.29`、`.200` 各发送 2 个 Echo Request，超时 400 ms。
- 读取 Win7 的 `arp -a`，将应答 IP 与动态 ARP 映射关联。
- 没有回应只表示本次没有收到 ICMP Echo Reply，不代表主机不存在或离线。

## 7.3 二层地址与 OUI

对本次有响应的邻居读取 ARP 缓存：

- 14 个其他可达地址中，13 个的 MAC OUI 为 `44:37:E6`。
- `192.168.236.200` 的 MAC OUI 为 `F4:4D:30`。
- `44:37:E6` 的公开 OUI 注册名称为 Hon Hai Precision Ind. Co., Ltd.（鸿海精密）。参考：[MAC Vendor Lookup](https://www.macvendorlookup.com/search/44%3A37%3AE6%3A00%3A00%3A00)、[IEEE OUI 查询镜像](https://hwaddress.com/oui-iab/44-37-E6/)。
- `F4:4D:30` 的公开 OUI 注册名称为 Elitegroup Computer Systems Co., Ltd.。参考：[MACDetect](https://macdetect.com/oui/F44D30)、[HWAddress](https://hwaddress.com/oui-iab/F4-4D-30/)。

OUI 只能说明 MAC 地址块的注册组织，无法单独识别整机品牌、具体网卡型号或设备用途。大量地址共享 `44:37:E6` 前缀，可能反映同一网卡供应商或设备供应链，不能据此断言设备型号一致。

为避免公开第三方终端的稳定标识，本文只记录 OUI，不保存完整邻居 MAC 地址。

## 7.4 TTL 观察

本次收到的邻居 Echo Reply TTL 分布：

- TTL=64：`.10`、`.12`、`.28`、`.29`、`.40`、`.41`、`.42`、`.44`、`.45`、`.47`、`.48`、`.50`。
- TTL=128：`.20`、`.25`、`.200`。
- Win7 自身 `.49` 的本机 Echo Reply 显示 TTL=64。

64 和 128 常见于不同操作系统的默认初始 TTL，但操作系统可修改该值，且中间路由也会递减 TTL。这里的目标都在同一 /24，通常为直接二层邻居，因此初始 TTL 的差异值得关注；仍不能仅凭 TTL 确定 Windows、Linux、Android 或其他系统。

## 7.5 对拓扑研究的意义

1. Win7 所在的 `192.168.236.0/24` 至少有 14 个其他地址在本次短采样中回应 ICMP，说明这不是只有 Win7 一台设备的孤立网段。
2. 多数可达邻居共享同一 OUI，可能是一个具有相对统一终端硬件来源的教室/实验室网络；这一点需要结合现场设备观察验证。
3. 邻居 MAC 均通过 Win7 的本地接口 ARP 获得，支持它们与 Win7 处于同一个 IPv4 链路子网。它们是否连接在同一物理交换机、同一 AP 或同一 VLAN，单靠 ARP 不能确定。
4. `.20`、`.25`、`.200` 返回 TTL=128，而其他大多数设备返回 TTL=64，可能存在混合终端系统。
5. 未响应的地址可能没有分配、设备休眠、禁用 ICMP 或过滤 Echo Request。不得将无响应直接记为离线。

## 7.6 下一步

在用户继续授权的前提下，可以对指定邻居做更有针对性的只读识别，例如对单个地址查询 NetBIOS 名称或进行用户指定的服务连通性测试。不要将当前结果扩大解释为整个子网的完整资产清单，也不要在没有额外授权时对邻居进行端口扫描或认证尝试。

本次测试没有修改 Win7、网关或邻居设备的配置。
