# 03-TTL 与路由路径观察

> 状态：占位待写。本篇计划记录如何通过 TTL、`traceroute` / `tracert` 和 ICMP Record Route 观察校园网内的路径变化。

## 3.1 想回答的问题

- TTL 为 64、63 时，分别暗示数据包经历了几跳三层转发？
- 宿舍、教室、不同 AP 下的第一跳是否稳定指向当前区域网关？
- 修改本机网关、Prefix Length 后，实际路径是否真的改变？
- ICMP Record Route 的结果能否辅助确认路径对称性？

## 3.2 已有线索

- 在同一 AP 内部，手动确认二层邻居后，互 Ping 曾出现 TTL 为 64 的情况。
- 跨 AP 或跨区域时，TTL 常见为 63，说明路径大概率经过了三层设备。
- 即使手动修改网关，第一跳仍可能由当前网络环境决定，而不是完全由本机配置决定。

## 3.4 初步判断

TTL 适合作为判断“是否经过三层转发”的轻量线索，但不能单独证明完整路径。后续应结合 `traceroute`、Record Route、BSSID、ARP 表和 DHCP 分配结果一起看。
