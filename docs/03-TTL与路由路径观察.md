# 03-TTL 与路由路径观察

> 本篇结论：TTL、traceroute、ARP 邻居表可以互相补充，帮助还原校园网的逻辑路径。当前实测显示，Win7 有线与宿舍 Wi-Fi 经过不同的校园内部节点和公网出口；多个区域候选网关又共享同一个二层邻居 MAC。所有设备角色判断都需要与真实管理配置区分。

## 3.1 TTL 应该怎样读

IPv4 TTL 是转发寿命字段。三层路由器转发数据包时通常将 TTL 减 1；TTL 到期后，路由器可能返回 ICMP Time Exceeded。Ping 输出的 TTL 是**回复包到达本机时的剩余 TTL**，并非经过的路由器数量。

常见初始 TTL 值包括 64、128、255，但系统和网络设备可以修改。只有知道目标的初始 TTL，才能粗略估算回复路径上的跳数。不同目标返回 TTL=64、128 或 255，不能单凭数值识别操作系统或设备型号。

本次观测中的例子：

| 来源 | 目标 | 回复 TTL | 备注 |
| --- | --- | ---: | --- |
| Win7 | 192.168.236.254 | 255 | 本地默认网关 |
| Win7 | 192.168.229.253 | 63 | 第二跳 |
| Win7 | 49.122.23.254 | 62 | CERNET 地址段中的目标 |
| Win7 | 10.200.1.5 | 59 | 候选校园内部转发节点 |
| Win7 | 10.200.1.14 | 122 | 候选校园内部转发节点 |
| OpenWrt | 10.201.255.254 | 64 | 区域候选网关 |
| OpenWrt | 10.203.255.254 | 64 | 默认网关 |
| OpenWrt | 10.200.1.5 | 64 | 候选校园内部转发节点 |
| OpenWrt | 10.200.1.14 | 127 | 候选校园内部转发节点 |
| OpenWrt | 49.122.23.254 | 61 | CERNET 地址段中的目标 |

## 3.2 Win7 有线接入路径

Win7 当前配置：

- IPv4：192.168.236.49/24
- 默认网关：192.168.236.254
- 网卡：Realtek 千兆以太网
- 本地网关 ARP OUI：60:0B:03（H3C 注册前缀）

route print -4 只有本地 192.168.236.0/24、回环/组播路由及默认路由 0.0.0.0/0 → 192.168.236.254，没有 10.0.0.0/8 或 10.200.0.0/13 的专用路由。因此 Win7 发往校园 10.x.x.x 的数据包都会先交给本地网关。

到两个区域候选网关的追踪：

| 跳数 | 目标 10.201.255.254 | 目标 10.203.255.254 |
| --- | --- | --- |
| 1 | 无回应 | 无回应 |
| 2 | 192.168.229.253 | 192.168.229.253 |
| 3 | 49.122.23.254 | 49.122.23.254 |
| 4 | 10.0.2.97 | 10.0.2.97 |
| 5 | 10.0.4.2 | 10.0.4.2 |
| 6 | 10.201.255.254 | 10.203.255.254 |

到 10.202.255.254 则多出 10.199.1.2，在第七跳收到终点回复。10.202.255.254 是 OpenWrt 当前使用的客户端地址，不能与 10.203.255.254 这个候选区域网关混为一谈。

## 3.3 宿舍 OpenWrt 的路径

OpenWrt 当前：

- phy-sta1：10.202.255.254/13
- 默认路由：10.203.255.254
- SSID：HUEL_WIRELESS

到 CERNET 地址 49.122.23.254 的 UDP traceroute：

| 跳数 | 节点 |
| --- | --- |
| 1 | 10.203.255.254 |
| 2 | 10.199.1.1 |
| 3 | 10.0.4.1 |
| 4 | 49.122.23.254 |

到自有腾讯云服务器 62.234.68.123 的 UDP traceroute 样本：

| 跳数 | 节点 |
| --- | --- |
| 1 | 无回应 |
| 2 | 10.200.1.5 |
| 3 | 无回应 |
| 4 | 111.5.141.49 |
| 5–10 | 无回应 |

未回应的跳数不代表没有路由器，也可能是设备不返回对应的 ICMP 错误报文。OpenWrt 的 BusyBox traceroute 使用 UDP 探测；Windows tracert 使用 ICMP 探测，两者跳数不能机械地逐项比较。

## 3.4 共同的二层邻居 MAC 与 Proxy ARP

OpenWrt 对 10.201.255.254、10.203.255.254、10.200.1.5、10.200.1.14 的邻居表记录了相同的 MAC 前缀 28:D0:F5。其中 .201 与 .203 的完整邻居 MAC 完全相同，且与 OpenWrt 自身接口 MAC 不同。

这支持校园网存在 Proxy ARP、共享虚拟 MAC 或网关集群的解释。它不能证明这些 IP 背后只有一台物理设备，也不能由 OUI 直接识别具体型号。

## 3.5 两个候选出口节点

到同一个公网目标 62.234.68.123：

- Win7 路径出现 10.200.1.14 → 171.15.162.1，自有 Nginx 看到的直连源地址为 171.15.162.x，属于 AS4134 / CHINANET-HA。
- OpenWrt 路径出现 10.200.1.5 → 111.5.141.49，自有 Nginx 看到的直连源地址为 39.162.143.x，属于 AS24445 / 河南移动。

10.200.1.5 与 .14 因而是两个候选边界转发节点。它们分别与移动、电信出口路径高度相关，但目前不能确认它们是否执行 NAT，还是只负责中间转发。两者的 ICMP 回复 TTL 分别接近 64 与 128，也不能据此判断操作系统。

## 3.6 观察边界

- tracert 中的星号表示本次探测没有收到回应，不代表该跳不存在。
- ICMP TTL、Record Route 和 UDP traceroute 可能被设备过滤。
- 同一 ARP MAC 可能来自 Proxy ARP、VRRP、共享虚拟 MAC 或设备集群。
- 公网出口 IP 和 ASN 能证明外部可见的网络归属，不能定位 NAT 设备或校园内物理链路。
