# 04-流量路径与边界验证

> 本篇结论：校园网内互访、公网访问和不同接入方式的出口选择是不同层次的问题。当前已确认 Win7 有线与宿舍 Wi-Fi 对同一公网服务器使用不同的公网源地址和内部转发节点；系统代理已排除。NAT 的具体位置、登录状态与策略路由条件仍待验证。

## 4.1 研究范围

本篇只讨论本人获准接入的 Win7 教室有线终端、自有宿舍 OpenWrt，以及自有腾讯云服务器。测试没有尝试认证绕过、共享枚举、第三方终端服务探测或校园设备配置修改。

流量按三个目的地分类：

1. 本地接入子网：192.168.236.0/24 中的网关和邻居。
2. 校园内部网络：10.x.x.x 地址、区域候选网关及 CERNET 地址。
3. 公网：自有腾讯云服务器 62.234.68.123。

## 4.2 本地接入子网

Win7 使用静态地址 192.168.236.49/24，默认网关 192.168.236.254。路由表只有本地 /24 和默认路由，没有专门指向校园 10.x.x.x 地址块的静态路由。

在用户明确授权的少量同网段地址中，14 个其他地址在短时 ICMP 采样中有回应。多数回应地址的 MAC OUI 为 44:37:E6。它说明该子网内存在多台可达终端，但不能推断整个 /24 的在线设备数量，也不能确定物理交换机、VLAN 或楼宇位置。详情见 [07-Win7 同网段邻居与 ARP 采样](07-Win7同网段邻居可达性与ARP采样.md)。

## 4.3 校园内部地址与区域网关

Win7 到 10.201.255.254 和 10.203.255.254 的 traceroute 前五跳相同，分别经过 192.168.229.253、49.122.23.254、10.0.2.97、10.0.4.2，然后在第六跳到达不同候选网关。

OpenWrt 当前位于 10.202.255.254/13，默认网关为 10.203.255.254。它对 10.201.255.254 与 10.203.255.254 的 ARP 邻居解析到同一个二层 MAC 前缀 28:D0:F5。这个现象支持 Proxy ARP、共享虚拟 MAC 或网关集群等解释。

Win7 发往校园 10.x.x.x 地址时，仍然先交给 192.168.236.254；它并没有直接加入 10.200.0.0/13 的本地链路。因而东区 10.200.0.0/15、西区 10.202.0.0/15 的区域划分仍是有旁证的假设，Win7 的物理接入区域尚未确认。

## 4.4 到同一公网服务器的出口差异

通过自有腾讯云 Nginx 日志核对两端发出的唯一标记请求：

| 来源 | 本机 IPv4 | Nginx 观察到的源地址 | ASN / 运营商 |
| --- | --- | --- | --- |
| Win7 有线 | 192.168.236.49 | 171.15.162.x | AS4134 / 河南电信 |
| 宿舍 OpenWrt | 10.202.255.254 | 39.162.143.x | AS24445 / 河南移动 |

Win7 的 WinHTTP 代理为直接访问，当前用户 Internet Settings 的 ProxyEnable=0；.NET 默认代理解析返回原始目标 URL。随后使用原始 TCP Socket 直接连接自有服务器，Nginx 看到的来源仍为 171.15.162.x。因此这一差异不是由 Win7 的系统 HTTP 代理造成的。

OpenWrt 没有代理环境变量；ip route get 显示请求通过 10.203.255.254 发出，BusyBox wget 直接连接服务器。Nginx 看到的来源仍为 39.162.143.x。

这确认两种接入方式存在不同的公网出口/NAT 映射。它不能确定地址转换发生在校园汇聚、校园边界、运营商网络还是多级设备上。

## 4.5 两条候选公网路径

Win7 到公网服务器的可见路径：

| 跳数 | 节点 |
| --- | --- |
| 1 | 无回应 |
| 2 | 192.168.229.253 |
| 3 | 49.122.23.254 |
| 4 | 10.0.2.97 |
| 5 | 10.0.4.2 |
| 6 | 10.199.1.2 |
| 7 | 10.200.1.14 |
| 8 | 171.15.162.1 |
| 9 | 222.85.12.29（部分探测回应） |

宿舍 OpenWrt 到同一服务器的可见路径：

| 跳数 | 节点 |
| --- | --- |
| 1 | 无回应 |
| 2 | 10.200.1.5 |
| 3 | 无回应 |
| 4 | 111.5.141.49 |
| 5–10 | 无回应 |

因此 10.200.1.14 与电信出口路径相关，10.200.1.5 与移动出口路径相关。它们是候选边界转发节点，尚不能确认具体 NAT 功能或物理设备角色。

另一个共同点是，Win7 和 OpenWrt 都能到达 49.122.23.254。该地址位于 49.122.16.0/21，公开路由登记关联 CERNET / AS4538。两端到达它的内部路径不同：Win7 经 192.168.229.253；OpenWrt 经 10.203.255.254、10.199.1.1、10.0.4.1。它说明两种接入都能到达同一个教育网地址空间，不能单凭这一点证明完整物理拓扑。

## 4.6 已证实与待证实

**已证实：**

- Win7 本地网段为 192.168.236.0/24，默认网关为 192.168.236.254。
- Win7 没有指向校园 10.x.x.x 的专用静态路由。
- 宿舍 OpenWrt 使用 10.202.255.254/13，默认网关为 10.203.255.254。
- 多个区域候选网关和内部节点在 OpenWrt 邻居表中解析到同一个 MAC。
- 两种接入访问同一个自有公网服务器时，使用不同公网源地址。
- 排除系统代理后，Win7 原始 TCP 连接仍显示电信出口；OpenWrt 直接 HTTP 请求显示移动出口。

**待证实：**

- 10.200.1.5 与 10.200.1.14 是否为真正的边界路由器或 NAT 设备。
- NAT 发生在校园汇聚、校园边界还是运营商侧，是否存在多级 NAT。
- 出口选择究竟由接入位置、VLAN、SSID、有线/无线、账号策略还是多个条件共同决定。
- 10.202.255.254 的 ICMP 回复是否来自自有 OpenWrt。同步抓包未观察到 Win7 对应的 Echo Request，因此应答者身份仍未确认。
- 东区/西区 /15 地址块是否与实际地理区域一一对应。

## 4.7 下一步

1. 在同一地点分别用有线与 Wi-Fi 做直连出口对照，尽量分离“接入位置”和“接入类型”两个变量。
2. 在不同区域使用同一台自有设备和同一探测目标，观察公网出口是否随区域变化。
3. 如获得网络管理员提供的 VLAN、网关、NAT 或策略路由资料，再确认 10.200.1.5、10.200.1.14 的角色。
4. 先核实 10.202.255.254 的 ICMP 应答实体，再研究其回程路径。不要仅凭 Ping 成功推断应答设备身份。

详细原始观察见 [05-Win7 有线接入](05-Win7有线接入网关与跨域回程观察.md)、[06-区域分区假设](06-东区西区15分区假设与Win7教室接入定位.md) 和 [10-公网出口与 NAT 路径](10-校园网有线无线公网出口与NAT路径观察.md)。

**研究边界：** 不修改校园网 DHCP、ARP、认证、路由或防火墙配置；不收集第三方设备身份，不尝试绕过认证、计费或访问控制。
